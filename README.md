# Голосовой помощник-повар

> **Статус: в разработке.** Текущая версия — промежуточный этап переработки учебного проекта в полноценное приложение. Голосовой интерфейс пока не подключён к новому пайплайну.

Цель проекта — улучшить изначальный учебный голосовой ассистент для приготовления блюд и собрать из него рабочее приложение: поиск рецептов, сопровождение готовки и ответы на вопросы по шагам и ингредиентам.

Сейчас реализован текстовый RAG-контур: запрос пользователя → семантический поиск по базе рецептов → ответ локальной LLM.

## Что уже есть

- **PostgreSQL + pgvector** — хранение рецептов, ингредиентов, шагов приготовления и векторных представлений
- **EDA-скрипты** — разбор описаний датасета (время, кухня, ключевые слова)
- **RAG-пайплайн** — эмбеддинги, поиск ближайших рецептов, генерация ответа по найденному контексту
- **Локальная LLM через Ollama** — модель задаётся в `.env`, диалог идёт в терминале

## Стек

- Python 3.11+
- PostgreSQL 17 с расширением `pgvector` (Docker)
- Hugging Face датасет [epishchik/RuRecipes-93k](https://huggingface.co/datasets/epishchik/RuRecipes-93k)
- Sentence-Transformers (эмбеддинги, размерность 1024)
- Ollama (локальная генерация)
- psycopg, python-dotenv, langgraph (в зависимостях, агент на LangGraph ещё не вынесен)

## Архитектура на текущем этапе

```
запрос пользователя
        ↓
эмбеддинг запроса (Sentence-Transformers)
        ↓
поиск ближайших рецептов в Postgres (cosine / <=>)
        ↓
промпт + найденные рецепты + история диалога
        ↓
локальная LLM (Ollama)
        ↓
текстовый ответ в терминале
```

Схема базы:

- `recipes` — название, описание, ссылка, эмбеддинг
- `ingredients` — справочник ингредиентов
- `recipe_ingredients` — количество и единица измерения
- `steps` — шаги приготовления

Поиск пока опирается на название рецепта и список ингредиентов. Шаги и полный текст описания в retriever ещё не подаются.

## Структура проекта

```
src/
  main.py                 # CLI-цикл диалога
  agent/                  # RecipeAgent, системный промпт
  rag/                    # поиск и генерация ответа
  embeddings/             # загрузка модели эмбеддингов
  database/               # подключение, схема, создание таблиц
  assistant/              # исходный учебный ассистент (команды, состояния)
  speech/                 # исходные STT/TTS (Vosk, pyttsx3)
scripts/
  load_data.py            # загрузка датасета в Postgres
  generate_embeddings.py  # векторизация рецептов
  experiments/            # EDA
docker-compose.yml
.env.example
```

## Запуск

### 1. Окружение

```bash
python -m venv .venv
# Windows
.venv\Scripts\activate
# Linux / macOS
source .venv/bin/activate

pip install -r requirements.txt
cp .env.example .env
```

В `.env` задайте пользователя и пароль Postgres, имя БД, порт, имя модели эмбеддингов и имя модели Ollama (`LLM`).

### 2. База данных

```bash
docker compose up -d
python -m src.database.init_db
python -m scripts.load_data
python -m scripts.generate_embeddings
```

`load_data.py` по умолчанию берёт **1000** рецептов из датасета. Эмбеддинги считаются только для строк, где `embedding IS NULL`.

### 3. LLM и диалог

Нужен установленный [Ollama](https://ollama.com/) и скачанная модель, указанная в `LLM`.

```bash
python -m src.main
```

Выход из диалога: `выход`, `exit` или `quit`.

### EDA

```bash
python -m scripts.experiments.check_description
```
